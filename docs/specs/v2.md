# Houseful v2 spec

Written Sat 7 Nov 2026, about 01:30 IST. Submissions close at 09:00 IST, and the target is 07:00.

## Why

The first build works but reads as a demo: prices in ETH at a fixed rate, no accounts, one wallet hidden in the browser, no seats, one city of invented shows. v2 makes it an app a stranger can use without explanation.

## What changes

1. **Money.** USDT is the only settlement currency. Prices, escrow, refunds and host proceeds are all USDT. A fan can pay in USDT or in ETH, and ETH is converted through Uniswap inside the same transaction. A fan's refund is the same USDT amount they paid, whatever ETH does.
2. **Two logins.** Fans sign in at `/login`. Hosts sign in at `/host/login`. A fan account cannot reach the host console, and a host account has no fan wallet pages.
3. **Wallets.** An account has one or more wallets: the wallet built into the browser, plus any external wallet linked by signing a message. The user picks which one is active and can delink any wallet that holds no live ticket.
4. **World ID.** Connected once, on the account. One World ID can back one account. After that, buying needs no scan unless the show asks for a stronger credential than the account has.
5. **Recovery.** A ticket belongs to the verified person. Signed in on a new phone, they can move it to a new wallet. This also makes a sold wallet key worthless, because the original person can always pull the ticket back.
6. **Seats.** Seated shows have a seat map, and the buyer picks a seat. General admission shows skip that step. The chosen seat is on the ticket and enforced on chain.
7. **Real events, worldwide.** The catalog lists real events in cities around the world, with sources. It is a test network, so every listing says plainly that it is a test listing, is not affiliated with the artist or organiser, and links to the official seller. Listings use our generated posters, never artist photos or logos.
8. **Clear to a stranger.** Fan pages use plain words: price, date, seat, pay, ticket. Terms like nullifier, attestation and hash chain stay out of fan pages.
9. **Tested end to end.** Playwright covers every flow below, on a phone viewport as well as desktop.

## Contract interface

Keep the existing rules: no transfers, one per nullifier per event, spent attestations, bounded waitlist scan, separate proceeds and escrow, proceeds only after `endsAt`, refunds that cannot be blocked.

```solidity
constructor(address verifier, address usdt, address swapRouter, address weth, uint24 poolFee)

enum Purpose { None, Buy, Join, Claim, Recover }

struct EventParams {
    uint256 faceValue;      // USDT base units, 6 decimals
    uint256 capacity;
    bool seated;            // true: seat is 1..capacity. false: general admission, seat is 0
    uint64 saleStart;
    uint64 surrenderCutoff;
    uint64 endsAt;
    string metadataURI;
    bytes32 metadataHash;
}

// Pull faceValue USDT from msg.sender.
function buy(uint256 eventId, uint32 seat, uint256 nullifier, uint256 deadline, bytes signature) returns (uint256 ticketId);
function joinWaitlist(uint256 eventId, uint256 nullifier, uint256 deadline, bytes signature) returns (uint256 position);
function claimReturned(uint256 eventId, uint256 ticketId, uint256 nullifier, uint256 deadline, bytes signature);

// Same, paying in ETH. Swap msg.value through SwapRouter02.exactOutputSingle for exactly faceValue USDT, then return unused ETH.
function buyWithEth(uint256 eventId, uint32 seat, uint256 nullifier, uint256 deadline, bytes signature) payable returns (uint256 ticketId);
function joinWaitlistWithEth(uint256 eventId, uint256 nullifier, uint256 deadline, bytes signature) payable returns (uint256 position);
function claimReturnedWithEth(uint256 eventId, uint256 ticketId, uint256 nullifier, uint256 deadline, bytes signature) payable;

// Purpose.Recover. msg.sender becomes the owner. nullifier must match the ticket. Generation +1, door key cleared.
function recoverTicket(uint256 eventId, uint256 ticketId, uint256 nullifier, uint256 deadline, bytes signature);

function seatsTaken(uint256 eventId, uint32 fromSeat, uint32 count) view returns (bool[] memory);

event TicketBought(uint256 indexed eventId, uint256 indexed ticketId, address indexed owner, uint32 seat, uint256 nullifier);
error SeatTaken(uint32 seat);
error InvalidSeat(uint32 seat);
```

- `surrender`, `leaveWaitlist`, `claimRefund` and `withdrawProceeds` pay USDT.
- A ticket keeps its seat through surrender, waitlist promotion and `claimReturned`.
- The ticket view returns the seat.
- A test-only `MockSwapRouter` with a fixed rate of 1 ETH = 3,000 USDT lets local tests and end-to-end runs work offline. A separate live script proves the real Uniswap route on 1301.

`packages/contracts/deployments/<chainId>.json` holds `address`, `verifier`, `usdt`, `swapRouter`, `quoter`, `weth`, `poolFee`, `blockNumber`. `@houseful/contracts` exports them with `housefulAddress(chainId)`, `usdtAddress(chainId)` and `quoterAddress(chainId)`, plus `usdtAbi`.

## Streams

Two streams work at once. Each stays out of the other's files.

**Chain stream**
- `packages/contracts`: contract, tests, TestUSDT, MockSwapRouter, deploy, the pool, and the live Uniswap script.
- `lib/chain.ts`, `lib/contract.ts`, `lib/pricing.ts`, `lib/ticket-actions.ts`, `lib/host-actions.ts`, `server/attest.ts`, `app/api/faucet`, `scripts/seed-chain.ts`.
- The USDT rename in `format.ts`, `event-draft.ts`, the schema and display code (`formatUsdt`, `priceUsd`, `faceValueUnits`, `seated`).
- Checkout and seats: `components/ticket-panel.tsx`, `components/ticket-wallet.tsx`, `components/seatmap/*`, `lib/seat-layout.ts`, the `seated` option in `components/host/show-form.tsx`, the seat on the ticket.
- Deployment, hosting, and the real World ID run.

**Product stream**
- Accounts and sessions, `/login`, `/host/login`, `/account`, gating of `/host`.
- `lib/wallets/*`: linking, delinking and choosing wallets.
- World ID connection on the account, `/api/attest`, recovery flow.
- Catalog: `scripts/seed.ts`, real events, cities, timezones, city pages, search.
- Clarity pass on fan pages.
- Playwright suite in `apps/web/e2e`, `README.md`, `docs/`, `FEEDBACK.md`.

## Seams between streams

The chain stream keeps today's device wallet and `VerifyHuman` working until the product stream lands, then these replace them:

```ts
// lib/wallets/active.ts (product stream)
type Signer = { address: `0x${string}`; kind: "device" | "external"; client: WalletClient };
function activeSigner(): Promise<Signer>;

// lib/account/attest.ts (product stream). Calls POST /api/attest.
function requestAttestation(input: { eventId: string; purpose: "buy" | "join" | "claim" | "recover"; wallet: `0x${string}` }): Promise<Attestation>;
```

Every function in `lib/ticket-actions.ts` takes a `signer` as its first argument, so swapping the wallet source needs no changes there. Device wallets get gas and test USDT from the faucet. External wallets pay their own gas.

## Done means

A Playwright run passes these, at desktop and phone width:

1. Fan signs up, signs out, signs back in.
2. Host signs up separately, lists a show, and a fan account is refused from the console.
3. Fan links a second wallet, chooses it, delinks one. Delinking a wallet holding a live ticket is refused.
4. Fan connects World ID. A second account using the same World ID is refused, with a clear message.
5. Fan browses cities worldwide, sees dates in the city's timezone, and searches.
6. Fan picks a seat and pays in USDT. Another fan pays in ETH through the swap. A seat that was just taken is refused clearly.
7. The ticket shows the seat and a rotating door code. The door admits it, and rejects a stale code and a repeat entry, including offline.
8. Sold-out show: join the waitlist, a holder hands back, the seat moves to the next person, and the refund arrives in USDT.
9. Host cancels: fans refund themselves. After a show ends: the host withdraws.
10. Ticket recovery moves a ticket to a new wallet, and the old door code stops working.

World ID is stubbed at the network edge in these runs, with no bypass in the app. A real World ID run and the real Uniswap route on 1301 are checked separately and recorded in the README.
